## 作業ルール

- 指示がない限り lock ファイルを Edit / Write で直接書き換えない
- コード例やコメントのサンプル値に、実在の秘匿情報や個人・組織を特定できる値を使わない
- dotfiles に書くものは、コード・コメント・docs・rules・memory を問わず公開されるものとして扱う。業務や私的なリポジトリの固有名（repo・org・社内サービス名・worktree のパス）は、秘匿情報と同じく一般的な語に置き換える

## Claude 5 系モデルの調整

どちらの節が効くかは役割で決まり、セッションの主体か subagent かは問わない。「実行する側」は作業するエージェント自身の規律、「依頼する側」は他のエージェントに渡すプロンプトを書くときの規律で、渡した先に守らせるものではない。

skill が委譲や検証の手順を定めているときは、この節より skill を優先する。この節は常に読み込まれるので、こちらが skill の手順を上書きすると、skill が決めた委譲の構造が実行者の裁量で崩れる。

### 実行する側

- 調査や診断の結論を、要因の裏取りをせずに目の前の結果だけで出さない

### 依頼する側

- レビューや調査の依頼文に「重要な問題だけ」「保守的に」と書かない。実際のバグが報告の段階で落ちる。severity と confidence を付けて全件を報告させ、絞り込みは受け取った側で行う
- reasoning（内部の思考）を応答本文に書き写させる指示を書かない。宛先が Fable 5 だと refusal を招く
